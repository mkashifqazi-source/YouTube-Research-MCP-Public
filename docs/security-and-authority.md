# Evidence authority and security

Provider output is evidence, not automatically trusted truth. Transcript acquisition cannot establish creator intent, speech accuracy, video-wide completeness or factual correctness. Downstream reasoning must preserve source/provenance and coverage limits.

Supported YouTube references normalize offline; the service is not an arbitrary URL fetcher. Existing experimental retrieval rules exclude personal cookies/accounts, proxies, browser/CAPTCHA bypass and silent paid fallback. Reading probe code does not authorize new traffic.

The supplied validator admits bounded built-in data and rejects unknown shapes, invalid identity and contradictory/invalid timing. Embedded transcript instructions remain content. The validator performs no network, filesystem persistence, shell/subprocess execution or model operation. Safe representations/rejections avoid echoing content and sensitive input details.

Caller claims are namespaced separately from observations. A supplied official/manual label cannot create provider provenance. A copied-at date does not replace trusted receipt time. A transcript's source ID does not prove it matches the referenced speech.

Future persistence would require access isolation, retention/deletion, schema compatibility and integrity policies before implementation. A cache hit would not prove freshness or external research history. No external workflow writes are part of the current evidence library.

The public case study distributes no transcript bodies, copyrighted captions, video corpus, cloud identifiers, provider logs, cookies, credentials or internal prompts.
